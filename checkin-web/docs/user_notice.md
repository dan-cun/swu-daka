生效日期：2026 年 7 月 9 日

## 重要提醒

本系统的页面状态、执行日志、数据库记录和提示信息仅用于辅助判断程序是否完成请求。最终查寝打卡结果、签到状态、异常处理和相关后果，应以学校目标系统、钉钉端或其他官方渠道中的实际记录为准。

本系统不保证 100% 的打卡成功率，不提供任何明示或暗示的可用性、连续性、准确性或成功率担保。使用者在每次查寝打卡后，应自行前往钉钉端、学校目标系统或其他官方渠道复核最终状态。

使用本系统前，请你确认自己有权使用所提交的账号信息，并确认该使用方式符合学校、学院、宿舍管理及相关平台规则。若因违反相关规定造成后果，由使用者自行承担。

**核心提示：本系统为非官方辅助工具，可能因网络、登录、验证码、接口变更、定位校验、目标系统维护或程序缺陷导致打卡失败。打卡后请务必自行复核官方系统状态，因未复核或不当使用造成的后果由使用者自行承担。**

## 一、服务内容

本系统当前计划和已实现的能力包括：

1. 通过账号密码登录学校统一认证相关页面，获取后续请求所需的临时登录凭据。
2. 同步当日查寝打卡任务，包括表单 ID、发布 ID、业务键、签到时间段、签到地点和签到范围等必要信息。
3. 在定位校验通过后，向目标系统提交查寝打卡请求。
4. 记录必要的执行日志、接口摘要、任务状态和错误信息，便于排查失败原因。
5. 使用本地 SQLite 数据库存储用户信息和账号凭据，为后续网页管理界面提供基础数据。

本系统仍处于开发和测试阶段，部分模块仅为占位设计，包括但不限于密码加密、日志自动清理、网页端完整管理、后台任务队列、权限控制和异常通知。占位功能未完成前，不应视为已经具备正式服务能力。

## 二、账号与凭据

你应仅提交本人合法持有并被授权使用的账号、密码、学号及相关信息。不得使用他人账号，不得冒用他人身份，不得未经授权为他人执行查寝打卡。

当前系统支持将账号信息写入本地 SQLite 数据库，用于后续自动化流程。数据库文件默认保存在：

```text
checkin-web/data/app.db
```

该数据库属于本地运行数据，不应提交到 Git 仓库，不应上传到公开平台，不应发送给无关人员。

在正式加密模块完成前，凭据字段可能以临时明文标记形式保存。该状态仅适合本地开发和受控测试，不适合作为公开部署或多人长期使用方案。后续应将临时凭据迁移为加密存储。

## 三、用户确认与留痕

为确保使用者已阅读并理解本须知，后续网页端应在首次使用、添加账号、保存凭据或执行打卡前展示强制确认弹窗。弹窗应包含核心风险提示，并要求使用者主动勾选或点击“我已阅读并同意用户须知”。

系统可在本地 SQLite 数据库中记录用户同意状态，包括：

```text
has_agreed_terms
agreed_at
```

该记录仅用于证明使用者曾在本地系统中确认过本须知，不代表学校、学院、宿舍管理部门、钉钉或任何官方机构认可本系统，也不免除使用者遵守相关规则的义务。

## 四、打卡执行规则

本系统会优先同步当日查寝任务，并使用服务端返回的当日 `businessKey` 执行提交。静态默认值只作为兜底参数，不应长期依赖。

若同步结果显示当日任务已签到，系统默认不重复提交。如确需再次提交，应由使用者自行确认必要性和风险。

若定位校验结果显示不在签到范围内，系统应停止提交，不应绕过范围校验。

若账号密码错误、统一认证失败、验证码识别失败、登录凭据失效、目标接口变更、网络异常或目标系统维护，打卡可能失败。使用者应及时查看日志，并在官方系统中复核最终状态。

## 五、数据与日志

系统可能在本地保存以下数据：

1. 用户名、展示名、学号等基础用户信息。
2. 学校账号及其临时凭据存储内容。
3. 当日查寝任务信息。
4. 打卡执行记录、接口状态、错误信息和审计日志。
5. 临时 token、缓存文件、网络调试日志和 SQLite 数据库文件。

以下文件或目录属于运行数据或敏感数据，不应提交到 Git 仓库：

```text
token.txt
checkin_cache.json
audit_logs/
network_logs/
run_logs/
checkin-web/data/*.db
.env
```

日志仅用于排查问题和审计执行过程。日志中如包含 token、cookie、session、密码、请求头或其他敏感字段，应进行脱敏处理或限制访问。

使用者应定期清理不再需要的日志和缓存。删除日志通常不会影响后续打卡，但会影响事后排查；删除数据库会丢失已保存的用户信息和凭据。

## 六、安全注意事项

请妥善保管账号、密码、token、数据库文件、日志文件和截图。不要将登录页面、二维码页面、数据库文件、审计日志、调试报文或后台页面随意发送给他人。

当前系统尚未完成正式加密方案时，不建议在公共电脑、多人共用电脑、网盘同步目录或公开服务器中保存真实账号密码。

如果怀疑账号、密码、token 或数据库泄露，应立即：

1. 修改相关账号密码。
2. 删除本地 `token.txt`、缓存文件和可疑日志。
3. 检查 Git 暂存区和提交历史是否包含敏感数据。
4. 重新生成或清理本地数据库中的凭据记录。

## 七、用户行为规范

使用者不得将本系统用于以下行为：

1. 冒用他人账号或未经授权替他人打卡。
2. 批量测试账号密码、恶意请求接口或绕过系统限制。
3. 对学校系统、钉钉系统或本系统进行压测、攻击、扫描、破解或数据抓取。
4. 将本系统作为商业代打卡、转卖服务、接口转发服务或其他超出小范围自用目的的工具。
5. 在学校大群、贴吧、社交媒体、公开仓库、论坛或其他公开渠道传播本系统链接、源代码、部署方式、数据库文件、接口参数或使用教程。
6. 任何违反学校规定、平台规则、法律法规或公共秩序的用途。

如发现异常使用、未授权使用或明显风险行为，系统维护者可以暂停相关账号、本地任务或服务入口。

## 八、风险说明

使用本系统前，你应理解并接受以下风险：

1. 统一认证流程、验证码、风控策略或接口参数变化可能导致登录失败。
2. 学校目标系统或钉钉端页面变化可能导致任务同步失败。
3. 网络异常、服务维护、token 失效、浏览器环境异常可能导致执行中断。
4. 页面展示状态、数据库状态和日志状态可能与官方系统最终记录存在延迟或差异。
5. 自动化脚本可能因程序缺陷、配置错误、数据过期或第三方系统变更而失败。
6. 本地数据库、日志和缓存若管理不当，可能造成账号信息泄露。

如查寝打卡事项对你具有重要影响，请务必在学校官方系统或钉钉端自行复核，不应完全依赖本系统。

在合理范围内，维护者会尽量保留必要的错误信息和审计记录，以便定位问题。但对于因用户配置错误、账号异常、目标系统变化、网络异常或违反规则使用造成的结果，维护者不承担超出实际控制范围的责任。
